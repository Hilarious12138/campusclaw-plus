# 安全能力建设与已有模块转换

## Why

Plus当前只有工程骨架；GD已有认证、材料、检索、AI应用/Skill、MCP与测试，可减少重复开发，但旧工程的分层、接口和权限上下文不等于Plus规范。目标是在独立环境验证候选模块，按Plus设计转换，并把安全检查、业务审计和可靠异步作为每阶段交付条件。

## What Changes

1. 固定Plus与GD候选基线，先检查再转换；复用算法和已验证行为，不复制旧工程结构、数据或密钥。
2. 按“安全门禁/审计基础→认证和班级→材料与可靠异步→检索→AI应用/Skill/MCP→综合验收”交付，每阶段通过后再继续。
3. 建立SEC-01—08固定复测矩阵、SQL/XSS/跨站请求反例、真实红绿门禁、七列审计及四步AI攻击实验。
4. 把材料处理接入已有异步设计，统一验证202、停机恢复、重复只生效一份结果；不迁移旧后台goroutine作为可靠队列。
5. 提供只依赖Docker的安全/功能自动验收、HTML/JSON及固定报告路径；缺业务、依赖、证据不能标绿。

## Capabilities

### New Capabilities
- `secure-platform-capabilities`：受控转换、身份/资源授权、安全检查、审计与分阶段业务验收。

### Modified Capabilities
无；长期能力仅在实际实现并验收后同步。本次只产出计划。

## Non-goals

不修改GD；不整体复制GD仓库，不迁移GD账号/数据库/向量/会话/密钥/历史；不本轮建设作业评分、教师改分、学情或公网部署；不承诺模型永不受提示词诱导；不默认引入Cookie登录或数据库密钥托管。不自动轮换真实密钥或重写远端历史。

## Alternatives / Maintenance

放弃整包复制后补安全：会带入旧App耦合、接口差异和未验证边界。选择在独立快照验证候选、逐模块重构并迁入对应测试。维护者承担三种职责，AI、脚本、自审分别记录；独立人类交叉评审未做仍记未完成。
