# 安全开发规范

适用：任何实现或配置变更。每次交付区分实际业务验证、测试替身与未接入的真实AI服务。

## 授权与文件读取

**要求**：默认拒绝，只开放明确登记的工程接口。业务请求逐项校验角色、班级和本人归属；班级从认证身份读取。跨班访问与资源不存在统一返回404。

文件读取必须关联业务资源并鉴权。不提供仅凭file_id读取任意文件的接口，不把uploads目录暴露给Nginx。

检查：未登记API及当前`/uploads/*`均不可访问。业务实现后覆盖水平越权、功能越权、匿名和他班文件读取，确认无数据返回。

## 秘密与轮换

**要求**：代码入库前，`.gitignore`就要忽略`.env`。真实秘密不得进入源码、前端、镜像层、日志或报告；`.env.example`只写`KEY=`。新建独立DB账号，不复用GD。

密钥泄露后，由维护者立即撤销或轮换、重启、验证旧值失败/新值成功，再扫描历史。只记录键名和结果，不记录密钥值。

检查：扫描全部Git历史和产物，构建上下文排除`.env`，镜像仅在运行时注入秘密。按`docs/deployment.md`验证轮换步骤。

## 令牌

**要求**：JWT访问令牌只存在内存，不放入URL或localStorage。业务实现时明确过期和退出撤销规则，不能为展示记录令牌。

检查：查看浏览器存储、日志，并验证撤销。首版无认证Cookie；跨站反例按Bearer、Origin和CORS检查，未来引入Cookie先补CSRF防护。

## 输入与输出

**要求**：校验字段类型、长度和允许的枚举值。SQL使用参数绑定，React按文本输出，不用`dangerouslySetInnerHTML`。外部材料、导入Skill和工具输出都先视为不可信。

检查：覆盖超限、类型错误、标签和SQL载荷，运行危险写法检查。

## 出站调用

**要求**：外部调用经过适配器，只允许配置白名单中的目标；重定向不能携带凭证。工具通过业务服务调用。内部DB/队列/向量服务使用固定Compose地址；MCP需精确origin白名单和受控DNS，禁止携带凭证重定向。

检查：列出出站点。未来提交内网或未知地址时，不得产生请求。

## 依赖与漏洞

**要求**：新依赖说明用途和许可证，允许MIT/BSD/Apache-2.0/ISC及已审查的上游组件。固定锁文件与镜像摘要。每PR、每周扫描；未豁免的高危/严重漏洞阻断，48小时内处理。

检查：运行`make audit`；公告源不可达记为未验证，不能算通过。

已审查的额外许可：MySQL驱动go-sql-driver/mysql为MPL-2.0，不修改其源文件；edwards25519为BSD-3-Clause；MySQL镜像含GPL-2.0上游组件，保留声明。React/Vite/TypeScript/Playwright及直接类型依赖的用途和许可仍纳入审查；上游许可不等于本项目选定了LICENSE。

新增依赖许可：golang-jwt/jwt/v5为MIT、golang.org/x/crypto与x/sys为BSD-3-Clause、rabbitmq/amqp091-go为BSD-2-Clause、swagger-ui-dist为Apache-2.0；分别用于Bearer校验、密码哈希、AMQP与本地接口文档。RabbitMQ镜像为MPL-2.0组件，Qdrant为Apache-2.0组件，继续保留上游声明。版本与镜像摘要锁定，每次交付重新审计。
