# 测试规范

| 约定 | 检查方式 |
| --- | --- |
| 测试由spec派生，按normal/failure/boundary命名；单元测试覆盖配置与规则，HTTP覆盖接口，浏览器/运行覆盖主链路。 | verification能力-Scenario两列表与测试标识逐项对应。 |
| 一键`make check`跑静态规范/历史秘密/Go单测与race/vet/前端状态测试/类型及构建/OpenSpec strict；任一非零即失败，不吞错误不留已知失败。 | 故意改坏一条规则，门禁必须失败；禁止生成空报告冒充。 |
| `make acceptance`为真实Compose/HTTP/依赖/日志/停机/浏览器验收，与单测替身分开标注；产物报告落reports/不提交秘密。 | docs记录命令、退出码、提交号、环境和限制。 |
| 单元测试用可注入DB探针和时钟，不联网；真实验收用独立Plus项目/卷或干净clone，不读取GD数据。 | DB故障只操作Plus；测试顺序打乱仍过。 |
| 本系统有独立业务code：OK才表示成功；拒绝码+无副作用+无泄露才是拒绝，不能只看HTTP。网关无JSON体按协议状态。 | 分别构造code失败/泄露/DB变更检查，不将HTTP200等同业务成功。 |
| 缺陷词：负向出现OK/意外写入/泄露为“被当成成功”；权限负向读写生效为“被放行”；正常无OK/副作用为“被误拒”；堆栈/泛化错误/挂起为“未处理故障”。 | 每条失败用例按这些信号写判据；若规约无机器码，不自行编造，记缺口。 |
| 健康探测本机正向>500ms标慢、>2000ms失败；负向受配置1500ms探测上限+网络容差约束。 | acceptance记录耗时，超限不改阈值凑通过。 |
| 每次修复先复现；测试必须能发现逻辑被改坏。未来12条AI评测与鉴权/作业状态专项同样由spec派生。 | 分层违规与未知路由放行变异测试；当前只声明AI评测未实现。 |
