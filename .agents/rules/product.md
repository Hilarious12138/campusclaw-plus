# 产品设计规范

| 约定 | 检查方式 |
| --- | --- |
| 用户为教师/学生；本课首页面向项目验收者，只有工程状态，无教学业务入口。未来页面与角色须先写入spec。 | README用户/路由与Scenario反向对照；缺入口/孤立入口判缺陷。 |
| 当前路由仅/；未知页面404，不SPA吞掉错误。/health、/live是工程接口，不是业务页。 | HTTP访问/不存在路径；预期404。 |
| 数据视图四状态：加载“正在检查服务…”；正常“服务已就绪”；错误“服务暂不可用，请稍后重试”；空“未返回可用状态，请重试”。错误保留重试按钮。 | 前端状态单测覆盖pending/ready/error/empty，真实页面验收健康/故障。 |
| 术语固定：AI应用、提示词模板、知识库材料、技能Skill、工具MCP、作业、错题、学情；骨架只显示工程状态。 | 搜索新增界面文案与术语表比对。 |
| 间距4/8/12/16/24/32px，字号12/14/16/24/32px；使用CSS变量，不引入一次性组件库；语义色成功绿/故障红。 | CSS与页面走查；320/768/1280px无横向溢出。 |
| 控件有label/可访问名称，键盘可达，反馈区role=status或alert。 | Tab、Enter测试；浏览器测试检查accessible name。 |
| 表单失焦校验且提交统一校验；忙时禁重复提交；导入先整批校验，错误含行号/字段，不部分写库。本课无表单导入。 | 相关业务Scenario配空/超限/重复/错误行用例；当前N/A。 |
| 流程先定枚举、流转与允许操作；终态默认不可改，教师改分走独立授权与审计入口；并发冲突409。 | 对每个状态尝试允许/禁止操作及并发；骨架工程状态由health结果派生。 |
