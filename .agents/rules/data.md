# 数据规范

适用：业务表、迁移、索引、材料/向量、个人数据、留存与删除变更。当前骨架只探测MySQL，尚无业务表；恢复/删除等业务验证仍待实施。

| 约束 | 检查方式 / 失败判据 |
| --- | --- |
| 表/字段snake_case、时间UTC；业务资源含id、归属与created_at/updated_at/created_by。班级资源必须有可校验的class_id。 | 迁移与模型逐项核对；缺归属、混用本地时间或客户端覆盖审计字段判失败。 |
| 班级从认证身份解析；查询、更新、删除均在数据访问条件中限定归属，不能先取全量再靠前端过滤。稳定排序以唯一id兜底。 | 以A/B班样本测试列表、详情、更新、删除及相同排序值分页；任何跨班数据/副作用或重复漏页判失败。 |
| 已发布迁移只新增，不编辑旧迁移；每次写兼容顺序、回滚或不可逆的备份/恢复方案。约束用事务与数据库唯一键兜底；事务中禁止模型/MCP调用。 | 空库升级、旧版本升级及回滚/恢复演练；已有数据丢失、版本不兼容或事务夹外调均阻断。 |
| 公开=状态版本；内部=配置键/索引；个人=账号、会话、作答；秘密=密码、令牌、模型/MCP密钥。密码仅哈希，服务密钥仅环境变量，数据库至多存密钥引用。 | 查字段设计、API投影与日志；明文密码、秘密入库/前端/Git/报告判失败；不要将账号登录密码与服务密钥混淆。 |
| 引入向量能力后，MySQL保存切片正文；向量记录与切片id关联并含过滤标识，不重复存放正文。 | 抽样向量回查MySQL并检查班级；孤儿向量、归属不一致或向量存正文失败；当前无Qdrant，不宣称已通过。 |
| 会话/审计默认留存30天，备份7天，业务spec可基于需要调整并记录理由。到期任务必须有失败报警与重试边界。 | 构造刚到期/未到期两条数据，核对只清理到期项；未执行任务或误删均失败。当前待业务落地。 |
| 删除前列出MySQL、向量库、对象/附件、缓存、备份副本；逐项记录已删、待到期或N/A。备份到期前不声称所有副本已消失，恢复时重放删除标记。 | 删除后分别查各存储；漏副本、已删数据恢复后复现、无到期时间却宣称删除完成均失败。仅骨架存储记N/A需说明原因。 |
| 业务上线后每日备份、保留7天，RPO≤24h/RTO≤30min；实施前安排独立恢复环境，不覆盖正式卷。 | 真实恢复后对比条数、关键关联/内容摘要并记录耗时；只存在备份命令不算通过，目标未达标阻断上线。 |
